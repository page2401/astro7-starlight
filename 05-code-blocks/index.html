05. 高阶代码块与语法高亮

技术文档中超过 40% 的篇幅由代码块构成，但标准 CommonMark / GitHub Flavored Markdown 仅定义了围栏语言标识（```ts），并未定义文件名标题栏、指定行高亮、带词法着色的行级 Diff 以及多语言 Tab 切换组。本页由原始 GFM 母版派生适配至 Astro 7 (7.4.13) + Starlight (0.43.1)，全面实测其开箱内置的 Expressive Code (astro-expressive-code) 引擎表现。

1. 代码块文件名标题栏与编辑器外框

Section titled “1. 代码块文件名标题栏与编辑器外框”

Starlight 内置的 Expressive Code 会根据语言自动区分“代码编辑器窗口”与“终端窗口”（如 bash / sh 自动渲染三圆点终端顶栏），只需在围栏信息串中声明 title="scripts/resolve-route.ts" 即可生成带标签页外观的文件名标题栏与一键复制按钮：

Section titled “3. 保留词法着色的代码增删对比（Diff + Syntax Highlighting）”

标准 GFM 使用 diff 语言块时会丢失底层 TypeScript 关键字词法高亮。Expressive Code 原生提供 del={2-3} 与 ins={4-6} 行级增删属性（亦支持 ```diff lang="ts" 双语法模式），在渲染红绿增删标记的同时完整保留 TypeScript 词法高亮：

Section titled “4. 多语言运行时命令组（<Tabs> + <TabItem>）”

由于本章节需要调用交互式横向标签页组件，文件扩展名由 .md 升级为 .mdx，并从 @astrojs/starlight/components 按需引入 <Tabs syncKey="runtime"> 与 <TabItem>（支持跨页面状态同步与无障碍键盘方向键切换）：

  • Node.js (package.json)
